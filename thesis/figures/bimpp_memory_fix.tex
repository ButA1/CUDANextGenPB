%  sparse_matrix_template memory fix: std::map -> boost::container::flat_map.
%  Hand-authored from two heaptrack captures (rank 1, 6VYB, 4 MPI ranks, both
%  using the AMGX solver): profiles/heaptrack.ngpb.rank1.base.zst (std::map)
%  and profiles/heaptrack.ngpb.rank1.opt.amgx.zst (flat_map).
%  Rank 1 rather than rank 0: the rank 0 opt.amgx capture is corrupted (all
%  memory attributed to one frame -- a truncated .zst from an OOM kill during
%  a later re-run attempt), while rank 1's is intact for both before/after.
%
%  TOTALS come from the Summary tab / heaptrack_print "peak heap memory
%  consumption" (6.62G and 3.72G), NOT from the Top-Down "main" row. Do not
%  substitute the Top-Down number here: the two captures unwind to different
%  depths, so they root differently. In base, every stack ends at main, so
%  Top-Down main (6.6G) ~= the whole process. In opt, the num_local_nodes ->
%  p8est -> libsc site (813M) unwinds past main into __libc_start_call_main
%  and roots under _start instead, so Top-Down main (2.8G) omits it while the
%  process peak is 3.72G. Using both Top-Down numbers would show a 2.4x drop
%  where the real like-for-like figure is 1.8x.
%  The assemble_system_matrix bars ARE the Top-Down Peak column; that node
%  roots through main in both captures, so it is comparable.
%  See [[project_bimpp_memory]].
%  Include with \input{figures/bimpp_memory_fix}
%  Needs \usepackage{pgfplots} in the preamble.
% ------------------------------------------------------------------------
